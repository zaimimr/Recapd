# Web Join Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Guests join an event from `https://recapd.app/join/CODE` in the browser, upload photos and videos, browse the live gallery and download everything, with no app.

**Architecture:** The existing Vite + React site in `web/` gets a code-split guest app on `/join/:code`. `web/api/join.ts` serves the SPA shell with server-rendered OG tags. The browser talks to Supabase directly with `supabase-js` (anonymous auth, RLS, TUS storage, realtime), exactly like the app. One migration enforces the participant cap on the server and exposes upload limits.

**Tech Stack:** React 19, react-router 7, Vite 7, `@supabase/supabase-js`, `tus-js-client`, `exifr`, `client-zip`, Vitest, Playwright (verification only), Supabase Postgres.

**Spec:** `docs/superpowers/specs/2026-09-30-web-join-design.md` (the "Decisions" sections are binding).

## Global Constraints

- No code comments. No em dash character anywhere. No attribution lines in commits.
- Hobby project: commit to `main`. Push and `vercel --prod` only in Task 6.
- Web is ESM on Vercel's Node builder: relative imports in `web/api/**` and `web/kit/**` end in `.js`. SPA code under `web/src/` is bundled by Vite (normal imports).
- Biome formatting (tabs, width 100): run `npx biome check --write <files>` from repo root before committing.
- Mirror the app's data contract exactly: storage paths `{eventId}/{profileId}/{Date.now()}_{rand8}.{ext}` and `{same base}_thumb.jpg`; `media_items` columns `event_id, uploaded_by_user_id, captured_at, media_type ('photo'|'video'), width, height, duration_milliseconds (video only), file_size_bytes, storage_path, thumbnail_path, visibility='shared'`.
- Display name 2-30 characters. Join code normalization: uppercase, 6 chars `A-Z0-9` (reuse `web/kit/event.ts` `normalizeCode`).
- No automatic upload retries (user mandate). Failed items show Retry.
- Supabase project `zfrpwfuihfpoqyexbwng`. Live test join code for read-only checks: `W6DD5K`. Never upload into or join real users' events during testing; Task 6 creates and removes its own test event.
- Dark Sunset Pop look: colors from `web/kit/theme.ts` (`#FF5E62`, `#FF2D8E`, `#8B2FE0`, `#0B0B12`), Inter, mobile first, no horizontal scroll at 375 px.

## Review Focus

1. Full event: the 13th guest on a free event must be rejected by the server, and the web shows the Full screen, not a generic error.
2. Upload that TUS reports done but storage lacks: verify object exists before inserting `media_items`.
3. HEIC or undecodable file: upload still succeeds without a thumbnail, grid shows a placeholder, not a broken image.
4. Video over the duration limit or file over the size limit: rejected in the tray before any bytes are sent, with the limit in the message.
5. Refresh or return in the same browser: lands in the gallery as the same guest, never creates a second participant.

### Task 3: Upload pipeline and tray

**Files:** Create `web/src/guest/upload/` (`limits.ts`, `metadata.ts`, `thumbnail.ts`, `paths.ts`, `uploadItem.ts`, `useUploadQueue.ts`, `UploadTray.tsx`), tests alongside in `__tests__/`. Add deps `tus-js-client`, `exifr`.

- [ ] `limits.ts`: fetch `get_event_upload_limits(eventId)`; pure `checkFile(file, meta, limits)` returning ok or a human message naming the limit ("Video is 45 s, max is 30 s").
- [ ] `metadata.ts`: image dims via `createImageBitmap` (fallback `Image`), video dims/duration via a `<video>` element `loadedmetadata`, `captured_at` from `exifr` `DateTimeOriginal` else `new Date(file.lastModified)`.
- [ ] `thumbnail.ts`: 512 px longest side JPEG quality 0.6 via canvas; video frame at 0.1 s; returns null when the browser cannot decode (HEIC on non-Safari).
- [ ] `paths.ts`: `buildStoragePath(eventId, profileId, ext)` and `thumbPath(storagePath)` matching the app format; extension from file name, lowercased, fallback from mime.
- [ ] `uploadItem.ts`: TUS to `${SUPABASE_URL}/storage/v1/upload/resumable` with headers `authorization: Bearer <access token>`, `x-upsert: false`, metadata `bucketName`, `objectName`, `contentType`, `cacheControl`, `chunkSize` 6 MB, fresh access token before start and on retry; thumbnail via `storage.from('thumbnails').upload`; verify original exists via `storage.from('event-photos').info(path)` (or `list` on the folder) with matching size before inserting; insert `media_items`. Throw typed errors: `too_large`, `too_long`, `network`, `verify_failed`, `rejected`.
- [ ] `useUploadQueue.ts`: concurrency 2, states queued/uploading(progress)/paused/failed/done, Retry resumes the same TUS upload, no automatic retry, Wake Lock while active, `beforeunload` warning while active, `visibilitychange` hidden → mark in-flight as paused on return if the request died.
- [ ] `UploadTray.tsx` + "Add photos & videos" button (`<input type=file multiple accept="image/*,video/*">`).
- [ ] Vitest for `checkFile`, `buildStoragePath`/`thumbPath`, EXIF fallback, queue state transitions (with `uploadItem` mocked).
- [ ] Commit.
